# Aurelia Residence

Интерактивный демо-шоурум вымышленной жилой башни **Aurelia Residence** в Business Bay, Дубай. Это не каталог и не лендинг с картинками: башня, поэтажные планы и проход по квартире — живые сцены Three.js (React Three Fiber + Drei).

Цены, статусы и планировки — демонстрационные и редактируются.

## Стек

- Next.js (App Router) + TypeScript + Tailwind
- Three.js, React Three Fiber, Drei
- GSAP и Framer Motion
- Prisma + PostgreSQL, с запасным режимом без базы
- Leaflet и тёмные тайлы CARTO (данные OpenStreetMap)

## Состав башни

35 надземных этажей:

- 1–2 — подиум (лобби, бассейн, фитнес, ресторан, спа)
- 3–32 — жилые этажи (по 4 квартиры)
- 33–35 — пентхаусы / sky villa (по 2 квартиры)

Четыре подземных паркинга описаны в данных и тексте, но в объём башни не входят — их не видно с улицы. Сигнатурная квартира из брифа: **A-3501**, этаж 35, 145 м², 2 спальни, 2 санузла, AED 2 450 000, статус Available.

## Локальный запуск

```bash
npm ci
npm run dev
```

Сайт: http://localhost:3000  
Админка: http://localhost:3000/admin

В режиме `next dev`, если `ADMIN_PASSWORD` не задан, пароль админки — `aurelia`. В production (`next start`, Render) без переменной админка закрыта.

Проверка production-сборки:

```bash
npm ci && npm run build
ADMIN_PASSWORD=aurelia npm start
```

Сервер слушает `0.0.0.0` и порт из `PORT` (по умолчанию 3000).

## Переменные окружения

Скопируйте `.env.example` в `.env`.

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | PostgreSQL. Если пусто, квартиры берутся из типизированного сида, правки цен/статусов пишутся в `data/overrides.json`, заявки — в `data/leads.json` и в память процесса. |
| `ADMIN_PASSWORD` | Пароль `/admin`. В production обязателен. |
| `TELEGRAM_BOT_TOKEN` | Необязательно. Бот для уведомления менеджера. |
| `TELEGRAM_CHAT_ID` | Необязательно. Чат, куда уходит заявка. |
| `SKIP_DB_PUSH` | `1`, чтобы `npm start` не вызывал `prisma db push`. |

Секреты в репозиторий не кладутся.

## База данных

Если `DATABASE_URL` задан, `npm start` в фоне выполняет `prisma db push`. При первом запросе пустая таблица квартир заполняется сидом. Если база недоступна или схема не создана, API молча переходит на сид и файловое хранилище заявок — первый деплой открывается и без живой Postgres.

Ручной пуш:

```bash
npx prisma db push
```

## Деплой на Render

В репозитории есть `render.yaml`:

- web service `aurelia-residence` (Node, план `starter`)
- Postgres `aurelia-db` (`basic-256mb`), строка подключения попадает в `DATABASE_URL`
- `ADMIN_PASSWORD` генерируется Render (`generateValue`)
- Telegram-переменные создаются пустыми (`sync: false`) — их нужно вписать в Dashboard
- health check: `/api/health`
- build: `npm ci && npm run build`
- start: `npm start` (слушает `0.0.0.0:$PORT`)

Можно задеплоить и один web service без базы: не задавайте `DATABASE_URL`, сайт останется на сиде.

## Управление в шоуруме

- Мышь / палец: вращение башни, колесо или щипок — зум
- Наведение и клик по этажу, либо список этажей слева
- На этаже: подсветка квартир, карточка, чипы для переключения
- **Enter apartment**: проход от первого лица
  - Desktop: WASD, мышь (pointer lock по клику), Shift — бег, стрелки — взгляд, ESC — выход
  - Телефон: джойстик слева, взгляд справа, кнопка Exit
- Стены и мебель не пропускают камеру
- День / закат переключаются кнопкой DAY / DUSK
- **Interested in this apartment** подставляет номер, этаж, площадь и цену

## Модули

`MainScene`, `BuildingModel`, `BuildingControls`, `FloorSelector`, `FloorScene`, `ApartmentSelector`, `ApartmentInterior`, `WalkController`, `ApartmentInfo`, `BookingForm`, `Navigation`, `AdminPanel`. Данные этажей и квартир — `src/data/building.ts`.

Сцены этажа и квартиры монтируются только когда пользователь до них дошёл. Слабые и мобильные устройства стартуют в низком качестве; `PerformanceMonitor` и `AdaptiveDpr` снижают нагрузку, если кадр проседает.

## Что процедурное, а что должно прийти из Blender

Сейчас **все** 3D-объекты собраны кодом: экструзия скруглённого плана, навесные витражи (canvas-текстуры), ламели, подиум с бассейном, корона, силуэт города, мебель квартиры. Сторонних GLB нет.

Позже имеет смысл заменить на лёгкие GLB из Blender (и сжать через gltf-transform):

- реальный фасадный модуль и корону вместо процедурного остекления
- лобби, бассейн и мебель (диван, кухня, кровать, санузел) — сейчас это собранные примитивы с PBR-материалами, читаемые как мебель, но не предметный дизайн
- уникальные планировки вместо одного представительного интерьера на все типы
- растения и антураж набережной

Текстуры фасада, камня, дерева, ковра и графики генерируются в canvas на клиенте, без внешних карт.

## Ограничения

- Интерьер один на все квартиры (отделка чуть зависит от типа). Это прогулка по типичной резиденции, а не уникальный меш каждой планировки.
- Коллизии — AABB, без лестниц и физики ткани.
- Заявки без базы живут в памяти процесса и в `data/leads.json`. На Render диск эфемерный: без Postgres заявки пропадут после рестарта.
- Галерея — те же процедурные ракурсы во втором WebGL-контексте, не офлайн-рендеры.
- Админка простая: цена, статус, список заявок.
